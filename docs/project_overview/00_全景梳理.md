# Operit AI — 项目全景梳理（从 0 到 1）

## 一、这是什么

**Operit AI** 是一个运行在 Android 8.0+ 上的 AI 智能助手应用。它的核心定位不是"聊天界面"，而是**把 AI 模型与 Android 系统权限深度融合的设备级 Agent**。

- 支持 18+ 家 AI 服务商（OpenAI/Claude/Gemini/DeepSeek 等）+ 本地模型（MNN/llama.cpp）
- 40+ 内置工具（文件、网络、Shell、UI 自动化、媒体处理等）
- 内嵌 Ubuntu 24 终端、QuickJS 脚本引擎、MCP 生态
- LGPLv3 开源，GitHub: AAswordman/Operit

## 三、架构分层详解

### 层 1：`api/` — AI 模型接入层

这一层负责与外部/本地 AI 通信，是所有 AI 能力的入口。

```
api/chat/
├── llmprovider/         # AI 服务商适配器
│   ├── OpenAIProvider.kt          # OpenAI（兼容接口通用）
│   ├── ClaudeProvider.kt          # Anthropic Claude
│   ├── GeminiProvider.kt          # Google Gemini
│   ├── DeepseekProvider.kt        # DeepSeek
│   ├── QwenAIProvider.kt          # 通义千问
│   ├── MNNProvider.kt             # 本地 MNN 推理
│   ├── LlamaProvider.kt           # 本地 llama.cpp 推理
│   ├── OllamaProvider.kt          # Ollama 本地服务
│   ├── ...（共 18+ 个）
│   ├── AIServiceFactory.kt        # 工厂：按配置选择 Provider
│   ├── RateLimitedAIService.kt    # 限速包装层
│   └── StructuredToolCallBridge.kt # 原生 ToolCall 协议适配
├── enhance/             # 对话增强层
│   ├── ConversationService.kt     # 主对话流程管理
│   ├── ToolExecutionManager.kt    # 工具调用执行协调
│   ├── MultiServiceManager.kt     # 多 AI 服务并发管理
│   └── InputProcessor.kt         # 用户输入预处理
```

**关键设计**：所有 Provider 实现统一的 `AIService` 接口，`AIServiceFactory` 根据用户配置动态选择。`RateLimitedAIService` 透明包装限速逻辑。

### 层 2：`core/` — 业务核心，最重要的一层

#### 2.1 工具系统 `core/tools/`

这是整个项目最核心的子系统，实现了 AI 调用设备能力的完整链路：

```
LLM 生成 tool call
    → ToolRegistration.kt（名称→执行器 映射表）
        → defaultTool/（分权限级别的执行实现）
            → 返回结果给 LLM
```

**权限分级架构**（同一个工具，不同权限下行为不同）：

| 目录 | 权限模式 | 说明 |
|---|---|---|
| `standard/` | 普通用户权限 | 沙盒内文件、HTTP、Shell 等 |
| `admin/` | Shizuku（ADB 级） | 通过 Shizuku IPC 获得更高系统权限 |
| `accessbility/` | 无障碍服务 | 通过无障碍服务控制 UI |
| `debugger/` | ADB | 通过 ADB 调试通道 |
| `root/` | Root | 完整 Root 权限 |
| `websession/` | Web 浏览器 | WebView 会话工具（含用户脚本注入）|

**工具选择器**：`ToolGetter.kt` 根据当前授权状态，自动选择该权限级别下的工具实现。

内置 19 个标准工具执行器，覆盖：
- 文件系统（标准 / SAF / Linux 文件系统）
- Shell 命令 / 终端
- HTTP 请求 / Web 访问
- UI 自动化（UITree 操作）
- FFmpeg 媒体处理
- 系统操作、广播、Intent
- 工作流控制、聊天管理工具

#### 2.2 JavaScript 引擎 `core/tools/javascript/`

应用内嵌 **QuickJS** 引擎，允许在 Android 上运行 JS/TS 编译的工具包脚本：

```
JsEngine.kt                  # QuickJS 引擎封装
JsTools.kt                   # Kotlin→JS Bridge，暴露 Tools.* API 给脚本
JsJavaBridge.kt              # 双向通信桥
JsExecutionScriptBuilder.kt  # 脚本执行上下文构建
JsToolPkgRegistration.kt     # 工具包注册
JsComposeDslBridge.kt        # Compose DSL 桥接（脚本可绘制 UI！）
```

#### 2.3 其他核心模块

```
core/chat/        # AI 对话引擎（AIMessageManager + hooks + plugins）
core/config/      # 工具 Schema 定义（SystemToolPrompts.kt ← LLM 的"说明书"）
core/mcp/         # MCP 协议客户端（连接外部 MCP 服务器）
core/skill/       # Skill 包系统（SkillManager + SkillPackage）
core/workflow/    # 工作流调度（WorkManager 驱动）
core/avatar/      # 桌宠/Avatar 系统
core/subpack/     # APK 编辑工具（反编译/回编）
```

## 四、脚本包系统（工具包生态）

这是 Operit 的"插件市场"核心：

```
TypeScript 源码 (examples/*.ts)
    ↓ 编译
JavaScript 产物 (examples/*.js)
    ↓ python sync_example_packages.py
应用内置包 (assets/packages/*.js)
    ↓ QuickJS 运行时加载
AI 调用 Tools.* API 执行
```

脚本可调用 `Tools.Files.*`、`Tools.System.*`、`Tools.Http.*` 等富 API，TypeScript 类型定义在 `examples/types/*.d.ts`。

**修改工具参数时必须同步 5 处**（见 `docs/DEFAULT_TOOLS_ARCH.md`）：Schema → 注册表 → Kotlin 实现 → JS Wrapper → TS 类型定义

## 五、核心数据流（一次 AI 对话的完整链路）

```
用户输入
    ↓
InputProcessor（附件处理、权限检查）
    ↓
ConversationService（上下文管理、记忆注入）
    ↓
AIService（Provider 发起 API 请求 / 本地推理）
    ↓  流式响应
AIMessageManager（消息管理、工具调用解析）
    ↓  若含 tool_call
ToolRegistration（路由）→ ToolGetter（按权限选择实现）→ 执行器
    ↓  执行结果
再次送入 AIService（多轮工具调用循环）
    ↓
StreamMarkdownRenderer（流式 KMP 渲染）
    ↓
Compose UI 更新（增量重组）
```

## 六、关键技术选型

| 技术 | 用途 |
|---|---|
| Kotlin + Jetpack Compose | Android UI，全声明式 |
| ObjectBox | 主数据库（高性能 NoSQL） |
| QuickJS（NDK） | 设备上运行 JS 工具脚本 |
| MNN / llama.cpp（NDK） | 离线本地 AI 推理 |
| Shizuku | 免 Root 的 ADB 级系统权限 |
| WorkManager | 工作流定时调度 |
| MCP 协议 | 标准化外部工具服务器接入 |
| KMP 算法 | 自研流式 Markdown 解析 |
