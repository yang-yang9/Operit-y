🔑 关键节点详解
📋
System Prompt 注入
每次请求前由 prepareConversationHistory() 动态构建：
工具描述 (Schema) ← SystemToolPrompts.kt 角色设定 ← CharacterCard / ActivePromptManager 记忆上下文 ← 记忆库向量搜索结果 工作区文件列表 ← 当前绑定工作区 思考引导 ← enableThinkingGuidance 开关 用户偏好描述 ← UserPreferences
🔀
工具权限路由
同一工具名，不同授权级别路由到不同实现（ToolGetter）：
Standard → defaultTool/standard/* Admin → defaultTool/admin/* (Shizuku) ADB → defaultTool/debugger/* A11y → defaultTool/accessbility/* Root → defaultTool/root/* JS 包 → PackageManager (QuickJS) MCP 服务 → PackageManager (MCP)
🔁
ReAct 工具调用循环
AI 输出 → 包含 <tool_call>? → 是则执行工具 → 结果放回历史 → 再次请求 AI
终止条件： ① AI 未输出任何 <tool_call> 标签 ② 达到最大工具调用轮次上限 ③ Token 超限 → 触发总结后自动续写 ④ AI 输出 <task_complete> 标记
⚡

📐 架构概览
Operit 采用 单一 Activity + 多 Composable 架构，使用自定义导航栈（非 Jetpack Navigation），支持手机和平板两种响应式布局。从 MainActivity.onCreate 入口，经 OperitApp 全局状态管理，到 PhoneLayout / TabletLayout 布局选择，再到 AppContent 的 Scaffold 容器，最终由 Screen.Content() 渲染具体业务页面。

📋 装配层级详解
层级组件职责
1. Activity MainActivity 生命周期管理、权限检查、通过 setContent 启动 Compose
2. OperitApp OperitApp 全局状态管理（currentScreen / backStack / topBarActions）、设备检测、布局分叉、导航逻辑
3. Layout TabletLayout / PhoneLayout 侧边栏/抽屉 + 内容区的排列方式
4. AppContent AppContent Scaffold（TopAppBar + 内容区）、屏幕缓存
5. Screen Screen.Content() 每个 Screen 子类渲染对应的具体业务页面
🧩 OperitApp 根组件
📊
状态管理
• currentScreen — 当前显示屏幕 • selectedItem — 侧边栏选中项 • backStack — 页面导航回退栈 • topBarActions — TopAppBar 动作按钮
🧭
导航函数
• navigateTo() — 跳转到目标页面 一级页面: 清空栈底, 压入 AiChat 二级页面: 直接压栈 • goBack() — 弹栈返回 兜底: 栈空时返回 AiChat
⚡
副作用 LaunchedEffect
• 快捷方式处理 (App Shortcuts) • 网络轮询 (NetworkPolling) • 公告拉取 (RemoteAnnouncement) • MCP 插件同步 (PackageSync)
🎨
覆盖层
RemoteAnnouncementDialog — 远程公告弹窗，在 OperitApp 根组件中直接渲染，覆盖在所有内容之上。

🔀 关键分支点
分支条件结果
布局选择 screenWidthDp >= 600 平板: TabletLayout / 手机: PhoneLayout
侧边栏形态 isTabletSidebarExpanded 展开: DrawerContent / 收起: CollapsedDrawerContent
返回按钮显示 currentScreen.isSecondaryScreen 二级页面显示返回箭头
TopBar Actions 由子屏幕通过 LocalTopBarActions 注入 AiChat/TokenConfig 有自定义按钮，其余页面清空
